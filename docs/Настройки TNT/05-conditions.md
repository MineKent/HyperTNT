# Условия активации (conditions)

Секция `conditions` ограничивает «успешную активацию» TNT. Если хотя бы одно условие не выполнено — активация блокируется и TNT не поджигается.

## Синтаксис

```yml
<id>:
  conditions:
    - "perm hypertnt.use.default"
    - "lvl 10"
    - "item GUNPOWDER 16 inv"
    - "!elytra"

  conditions-fail-message: "&cВы не можете активировать это TNT!"
```

---

## Логика выполнения

* Все условия выполняются по правилу **AND** (все должны быть истинны).
* **Короткое замыкание**: проверка останавливается на первом провальном условии.
* Если секция `conditions` отсутствует или является пустым списком — ограничений нет.

---

## Сценарии активации

Условия проверяются **до** поджига во всех точках активации:

| Сценарий | Игрок доступен? |
|---|---|
| Клик огнивом / огненным шаром | ✅ да |
| `auto-ignite-on-place` | ✅ да (тот, кто ставил) |
| Бросок | ✅ да |
| Поджиг от огня / лавы / взрыва | ❌ нет |
| Поджиг редстоуном | ❌ нет |

> [!IMPORTANT]
> Условия, требующие игрока (`perm`, `lvl`, `item`, `health` и др.), **всегда возвращают `false`** если игрок отсутствует — даже при использовании `!` (инверсии). Это предотвращает обход ограничений через редстоун/огонь.
>
> Условия, не требующие игрока (`world`, `height`, `underblock`, `nearby`), работают в любом случае.

---

## Сообщение при отказе

```yml
conditions-fail-message: "&cВы не можете активировать это TNT!"
```

* Отправляется игроку только если он присутствует в сценарии активации.
* Поддерживает `&`-коды цветов.
* Если не указано — сообщение не отправляется.

---

## DSL условий

Каждое условие — строка вида `[!]<тип> <аргументы...>`.

Префикс `!` инвертирует результат условия. Аргументы разделяются пробелами; строки с пробелами можно взять в кавычки `"..."`. Списки (миры, материалы) — через запятую без пробелов.

Операторы сравнения для числовых условий: `>`, `<`, `>=`, `<=`, `=`, `!=`. Если оператор не указан — используется `=`.

---

## Список условий

### `perm <node>`

Проверяет наличие права у игрока.

* `node` (обязательно) — permission node.

```yml
conditions:
  - "perm hypertnt.use"        # есть право
  - "!perm hypertnt.bypass"    # нет права
```

---

### `lvl <min>`

Проверяет уровень опыта (XP level) игрока.

* `min` (обязательно) — минимальный уровень.

```yml
conditions:
  - "lvl 10"     # уровень >= 10
  - "!lvl 10"    # уровень < 10
```

---

### `gamemode <режим>`

Проверяет режим игры игрока.

Допустимые значения: `SURVIVAL`, `CREATIVE`, `ADVENTURE`, `SPECTATOR`.

```yml
conditions:
  - "gamemode SURVIVAL"
  - "!gamemode CREATIVE"
```

---

### `elytra`

Проверяет, летит ли игрок на элитрах (`isGliding()`).

```yml
conditions:
  - "elytra"     # должен лететь на элитрах
  - "!elytra"    # не должен лететь
```

---

### `sprint`

Проверяет, бежит ли игрок (`isSprinting()`).

```yml
conditions:
  - "sprint"     # должен бежать
  - "!sprint"    # не должен бежать
```

---

### `sneak`

Проверяет, крадётся ли игрок (`isSneaking()`).

```yml
conditions:
  - "sneak"      # должен красться
  - "!sneak"     # не должен красться
```

---

### `ground`

Проверяет, стоит ли игрок на земле (`isOnGround()`).

```yml
conditions:
  - "ground"     # на земле
  - "!ground"    # в воздухе / прыжке
```

---

### `health <оператор><значение>[%]`

Проверяет здоровье игрока.

* Значение без `%` — абсолютные единицы здоровья (20 = 10 сердец).
* Значение с `%` — процент от максимального здоровья.

```yml
conditions:
  - "health <50%"   # меньше половины HP
  - "health >10"    # больше 10 единиц HP
  - "health =20"    # полное здоровье (ванильный макс)
```

---

### `food <оператор><значение>`

Проверяет уровень сытости игрока (0–20).

```yml
conditions:
  - "food >=18"    # почти сытый
  - "food <10"     # голодный
```

---

### `effect <EFFECT> [<оператор><level>]`

Проверяет наличие эффекта зелья у игрока.

* `EFFECT` (обязательно) — имя эффекта (`SPEED`, `INVISIBILITY`, `STRENGTH` и т.д.).
* `<оператор><level>` (опционально) — проверка уровня эффекта (в игровых уровнях: 1, 2, 3…).

```yml
conditions:
  - "effect INVISIBILITY"       # есть невидимость (любой уровень)
  - "effect SPEED >=2"          # скорость 2+ уровня
  - "!effect LEVITATION"        # нет левитации
```

---

### `item <MATERIAL> [AMOUNT] [inv|hand|mainhand|offhand]`

Проверяет наличие предмета в инвентаре игрока.

* `MATERIAL` (обязательно) — Bukkit-имя материала (например `GUNPOWDER`, `SHIELD`).
* `AMOUNT` (опционально) — минимальное количество. По умолчанию `1`.
* Слот (опционально):

| Значение | Область поиска |
|---|---|
| `inv` (по умолчанию) | Весь инвентарь |
| `hand` | Обе руки |
| `mainhand` | Только основная рука |
| `offhand` | Только дополнительная рука |

```yml
conditions:
  - "item GUNPOWDER 16 inv"     # 16+ пороха в инвентаре
  - "item SHIELD 1 offhand"     # щит в левой руке
  - "!item DIAMOND 1 inv"       # нет алмазов в инвентаре
```

---

### `itemmeta <where> <check> <value>`

Проверяет мета-данные предмета в руке.

* `where` — `mainhand` или `offhand`.
* `check`:

| Значение | Описание |
|---|---|
| `cmd` | Custom Model Data (число) |
| `name` | Отображаемое имя содержит `value` |
| `lore` | Любая строка лора содержит `value` |

```yml
conditions:
  - "itemmeta mainhand cmd 1234"
  - "itemmeta mainhand name Супер"
  - "itemmeta offhand lore Особый"
```

---

### `armor <slot> <MATERIAL>`

Проверяет материал брони в указанном слоте.

* `slot` — `head`, `chest`, `legs`, `feet`.

```yml
conditions:
  - "armor head NETHERITE_HELMET"
  - "!armor chest LEATHER_CHESTPLATE"
```

---

### `armormeta <slot> <check> <value>`

Проверяет мета-данные брони (аналогично `itemmeta`).

* `slot` — `head`, `chest`, `legs`, `feet`.
* `check` — `cmd`, `name`, `lore`.

```yml
conditions:
  - "armormeta head cmd 777"
  - "armormeta chest lore VIP"
```

---

### `slots <оператор><число>`

Проверяет количество свободных слотов в инвентаре игрока.

```yml
conditions:
  - "slots >=5"    # минимум 5 свободных слотов
  - "slots =0"     # инвентарь полон
```

---

### `world allow <миры>` / `world deny <миры>`

Проверяет мир, в котором находится TNT. Не требует игрока.

* `allow` — активация разрешена только в указанных мирах.
* `deny` — активация запрещена в указанных мирах.
* Миры указываются через запятую без пробелов.

```yml
conditions:
  - "world allow world,world_the_end"    # только в этих мирах
  - "world deny world_nether"            # запрет в незере
```

---

### `region allow <regions>` / `region deny <regions>`

Проверяет, находится ли TNT внутри регионов WorldGuard. Не требует игрока.

* Требует установленный **WorldGuard**.
* `regions` — список id регионов через запятую (без пробелов) или `*` для «любой регион».
* `allow` — активация разрешена только внутри указанных регионов.
* `deny` — активация запрещена внутри указанных регионов.

```yml
conditions:
  - "region allow spawn,market"   # только в регионах spawn или market
  - "region deny pvp"             # запрещено в регионе pvp
  - "region allow *"              # разрешено в любом регионе (если регионов нет — false)
```

> [!NOTE]
> Если WorldGuard не установлен (или API недоступен) — условие всегда `false` и один раз выводится предупреждение в консоль.

> [!IMPORTANT]
> Взрывы HyperTNT не «пересекают» границы регионов WorldGuard:
> блоки, которые находятся внутри региона, не будут затронуты взрывом TNT, стоящим снаружи.
> Также взрыв из одного региона не затронет блоки другого региона (если регионы не пересекаются).

---

### `height <оператор><значение>`

Проверяет координату Y места расположения TNT. Не требует игрока.

```yml
conditions:
  - "height >=64"    # на поверхности и выше
  - "height <0"      # ниже уровня моря
```

---

### `underblock <MATERIAL>`

Проверяет материал блока непосредственно под TNT. Не требует игрока.

```yml
conditions:
  - "underblock OBSIDIAN"     # стоит на обсидиане
  - "!underblock AIR"         # под TNT что-то есть
```

---

### `nearby <radius> <op> <materials>`

Проверяет наличие блоков указанных типов рядом с TNT. Не требует игрока.

* `radius` — радиус поиска в блоках.
* `op`:

| Значение | Описание |
|---|---|
| `any` | Хотя бы один блок найден |
| `none` | Ни одного блока не найдено |
| `count>=` | Найдено не менее N блоков (задаётся через `count=N`) |

* `materials` — материалы через запятую.

```yml
conditions:
  - "nearby 5 any WATER,LAVA"       # вода или лава в радиусе 5
  - "nearby 3 none BEDROCK"         # нет бедрока в радиусе 3
```

---

### `cooldown <seconds> [scope]`

Ограничивает частоту активации TNT по кулдауну. Кулдаун начинается **после взрыва** TNT этого типа.

* `seconds` — длительность кулдауна в секундах (можно дробное значение).
* `scope` (опционально) — область кулдауна:
  * `player` — кулдаун на игрока (по умолчанию).
  * `world` — кулдаун на мир.
  * `player,world` — одновременно на игрока и на мир (оба должны пройти).

```yml
conditions:
  - "cooldown 10"             # 10 секунд на игрока (в рамках мира)
  - "cooldown 5 world"        # 5 секунд на мир
  - "cooldown 20 player,world" # 20 секунд и на игрока, и на мир
```

> [!NOTE]
> Кулдаун хранится раздельно для каждого `id` TNT и мира. Для `scope: player` также учитывается UUID игрока.
> Если TNT взорвался без владельца (например, поджиг редстоуном/огнём), кулдаун уровня `player` может не примениться.

---

### `pnum <placeholder> <оператор><число>`

Числовая проверка значения PlaceholderAPI. Требует наличия PlaceholderAPI на сервере.

* `placeholder` — строка плейсхолдера (например `%player_level%`).
* Операторы: `>`, `<`, `>=`, `<=`, `=`, `!=`.

```yml
conditions:
  - "pnum %player_level% >=10"
  - "pnum %vault_eco_balance% >=1000"
  - "!pnum %player_level% >=10"    # уровень < 10
```

> [!NOTE]
> Если PlaceholderAPI не установлен — условие всегда `false`.
> Если плейсхолдер вернул не число — условие `false`.

---

### `pstr <placeholder> <op> <value>`

Строковая проверка значения PlaceholderAPI.

* `op`:

| Оператор | Описание |
|---|---|
| `=` | Строго равно |
| `!=` | Не равно |
| `contains` | Содержит подстроку |
| `icontains` | Содержит подстроку (без учёта регистра) |
| `matches` | Соответствует regex |

```yml
conditions:
  - "pstr %luckperms_primary_group_name% = vip"
  - "pstr %player_name% != Steve"
  - "pstr %server_name% contains lobby"
  - "pstr %some_tag% matches ^VIP_.*$"
  - "!pstr %luckperms_primary_group_name% = default"
```

> [!NOTE]
> Если PlaceholderAPI не установлен — условие всегда `false`.

## Примеры наборов

**Запретить активацию в полёте, требовать 16 пороха:**

```yml
conditions:
  - "!elytra"
  - "item GUNPOWDER 16 inv"
```

**Только в мирах `world` и `world_the_end`:**

```yml
conditions:
  - "world allow world,world_the_end"
```

**Требовать VIP-статус и баланс ≥ 5000:**

```yml
conditions:
  - "pstr %luckperms_primary_group_name% = vip"
  - "pnum %vault_eco_balance% >=5000"
```

**Требовать право, но запретить обход:**

```yml
conditions:
  - "perm hypertnt.use"
  - "!perm hypertnt.bypass"
```

**Полный пример типа с условиями:**

```yml
nuclear:
  enabled: true
  item:
    material: TNT
    name: "&4&lЯдерный заряд"
  conditions:
    - "perm hypertnt.use.nuclear"
    - "gamemode SURVIVAL"
    - "!elytra"
    - "lvl 30"
  conditions-fail-message: "&cНедостаточно условий для активации ядерного заряда."
  ignite:
    fuse-seconds: 5.0
  explosion:
    radius: 20.0
```

---

## Поведение при ошибках

Если строка условия содержит синтаксическую ошибку — в консоль выводится предупреждение и данное условие **считается невыполненным** (всегда `false`). Остальные типы TNT продолжают загружаться.
